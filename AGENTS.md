# Instructions for AI Coding Agents

## User and learning style

The repository owner is a beginner/intermediate learner who wants to build applications while gradually learning programming. Make practical progress and explain important concepts briefly when they become relevant. Do not turn every task into a programming lesson or overwhelm the user with unnecessary theory.

## Development guidelines

- Before making a major architectural change, explain the proposed approach.
- Prefer simple, maintainable solutions over unnecessary complexity.
- Do not add dependencies unless they provide a meaningful benefit.
- Keep projects isolated. When working on one project, do not modify unrelated projects.
- Preserve existing functionality when adding features.
- Test changes when practical, and clearly explain errors or failed tests.
- Never claim that something works if it has not been tested.
- Keep documentation synchronized with significant changes.
- Do not build a huge application before validating a smaller useful stage.
- If choosing technology for a new project, briefly explain the choice before implementing it.
- Break complicated work into sensible stages.
- Prefer working software over excessive abstraction.
- Do not install large frameworks or complicated infrastructure without a clear need.
- Explain unfamiliar terminology the first time it becomes important, but do not explain every line unless asked.

## Change reporting

After each meaningful stage, report:

1. What changed.
2. Why it changed.
3. How to test it.
4. Any important programming concept encountered.

For significant milestones, update `PROJECT_STATUS.md`, `CHANGELOG.md`, the relevant project README, and `LEARNING_LOG.md` when a meaningful concept was encountered.

## Git and sensitive information

Use logical commits with useful messages when the user asks for commits or the workflow clearly calls for one. Never commit or expose secrets, API keys, passwords, tokens, credentials, or personal sensitive information. Do not push to GitHub unless the user explicitly asks.

## Luna compatibility

Another AI assistant named Luna may inspect this repository without access to the conversation that created a change. Keep status, history, and project documentation concise and up to date. Do not record private conversations or sensitive personal information.
